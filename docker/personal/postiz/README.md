# Postiz

Social-media scheduler (Personal layer). Frontend + API + uploads on one hostname.

| | |
|---|---|
| Image | `ghcr.io/gitroomhq/postiz-app` — pinned via `POSTIZ_VERSION` (currently `v2.25.3`) |
| URL | <https://postiz.lab.marioverde.com.br> (LAN + Tailscale only, no WAN record) |
| Temporal UI | <https://temporal.lab.marioverde.com.br> (workflow debugging, LAN only) |
| Database | in-stack `postgres:17-alpine` (Postiz pins PG 17 and runs Prisma migrations on boot) |
| Cache / queue | in-stack `redis:7.2` |
| Workflows | `temporalio/auto-setup:1.28.1` on its own `postgres:16-alpine`, SQL visibility (no Elasticsearch) |
| Uploads | named volume `postiz_uploads` mounted at `/uploads` |
| Deployed by | Komodo stack `postiz`, run directory `docker/personal/postiz`, branch `master` |

## Deploy

Push to `master`, then from the komodo skill directory on the Hermes CT:

    python3 scripts/komodo.py deploy-stack postiz

That only deploys the commit Komodo already cloned. After a push, pull first — the bundled CLI has no
`pull-stack` subcommand, so call the API:

    curl -s -X POST "$KOMODO_ADDRESS/execute/PullStack" \
      -H "X-Api-Key: $KOMODO_API_KEY" -H "X-Api-Secret: $KOMODO_API_SECRET" \
      -H "Content-Type: application/json" -d '{"stack":"postiz"}'

Then assert `info.cloned_hash` == `master` HEAD, deploy, and assert `info.deployed_hash` == `info.latest_hash`
(the stack's `state` alone is not proof — check `read/ListUpdates` for `success: true`).

## Configuration (`.env`)

`docker/personal/postiz/.env` is **generated by Komodo on every deploy** from the stack's *Environment*
settings — it is never authored by hand, and a manual edit is lost on the next deploy. To change a value:
update the stack environment (`write/UpdateStack` with the full config), then pull + deploy.
`.env.example` is the versioned list of keys and contains no secrets.

## First boot

1. The **first account to sign in becomes the organisation owner**. Sign in with **Authentik** first.
2. Then create a local email/password account at `/auth` and promote it to Admin in
   *Settings → Team* — that is the emergency door if Authentik is down.
3. `RESEND_API_KEY` is deliberately **unset**, so no activation e-mail is required and new accounts are
   active immediately. Setting an email provider later switches activation back on.

## SSO (authentik)

| Setting | Value |
|---|---|
| Provider | OAuth2/OpenID, confidential, implicit-consent flow |
| Redirect URI | `https://postiz.lab.marioverde.com.br/settings` (strict match) |
| Scopes | `openid profile email` |
| Issuer | `https://auth.lab.marioverde.com.br/application/o/postiz/` |

Client id/secret live in the Komodo stack environment (`POSTIZ_OAUTH_CLIENT_ID` /
`POSTIZ_OAUTH_CLIENT_SECRET`), never in this repo.

**`DISABLE_REGISTRATION` must stay `false`.** Postiz documents that `true` also disables OIDC sign-in.
The compensating control is exposure, not the flag: the hostname resolves only inside the LAN/Tailnet.
Enabling a third-party OAuth app still disables the GitHub/Google login providers — that is expected.

## Deviations from the upstream compose

| Upstream | Here | Why |
|---|---|---|
| `ports: 4007:5000` on the app | no host port; Traefik routes to 5000 | Traefik runs `network_mode: host` |
| Elasticsearch 7.17 + `ENABLE_ES=true` for Temporal | SQL visibility, no ES container | ~1 GB of RAM on an 8 GB box already at ~3.5 GB; Postiz never uses advanced visibility |
| `temporal-admin-tools` | dropped | the `temporal` container already ships the CLI (`temporal operator cluster health` is its healthcheck) |
| `spotlight` (debug profile) | dropped | Sentry debugging, unused here |
| `postiz-config:/config/` volume | dropped | only needed for the `postiz.env`-file style of configuration |
| `container_name:` on every service | dropped | Compose project (= stack name) already gives stable names, and avoids collisions on recreate |

## Upgrade

Bump `POSTIZ_VERSION` in the stack environment **and** in `.env.example`, commit, push, then
`PullStack` + `DeployStack`. Prisma migrations run on boot. Never float `:latest` — Postiz ships
breaking env changes between minors.

## Rollback

    # containers only, data kept
    curl -s -X POST "$KOMODO_ADDRESS/execute/StopStack" ... -d '{"stack":"postiz"}'

To remove everything, delete the stack (Komodo `write/DeleteStack`) and
`docker volume rm postiz_postiz_postgres postiz_postiz_redis postiz_postiz_uploads postiz_temporal_postgres`
on docker01. The volumes hold the database — including every channel's OAuth token — so they are the
actual backup-worthy artifact.
